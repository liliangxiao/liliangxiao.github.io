# Pain Points and Countermeasures in Hard Real-Time Firmware Design under Resource Constraints
**资源受限下固件硬实时设计的痛点与对策**

## Abstract (摘要)
This article proposes the Punctual Reaction System (PRS) architecture as an engineering-oriented complement to traditional task-based scheduling. Rather than replacing existing real-time theories, PRS introduces a scenario-based layer that manages critical performance bottlenecks. This approach provides a practical framework for ensuring deterministic execution of high-value scenarios while maintaining compatibility with standard Rate Monotonic Scheduling (RMS) frameworks.
本文提出“准时反应系统 (PRS)”架构，作为对传统基于任务调度理论的工程化补充。PRS 并不取代现有实时理论，而是引入一个基于场景的层级，专项管理核心性能瓶颈。该架构在维持经典 RMS 任务调度框架兼容性的前提下，为关键场景的确定性执行提供了工程化实现路径。

---

## 1. Introduction (引言)
According to Stankovic (1988) [1], the correctness of a real-time system depends not only on the logical result but also on the time at which the result is produced. In practice, traditional scheduling theories (RMS/DMS) [2] effectively manage general-purpose task concurrency. However, when systems operate near hardware limits, these theories often face determinism challenges due to the gap between mathematical abstraction and physical engineering constraints. To bridge this gap, PRS is proposed not as an alternative, but as a scenario-based enhancement for critical physical contracts.
根据 Stankovic (1988) 的定义，实时系统的正确性依赖于逻辑结果与产出时刻 [1]。传统调度理论（RMS/DMS）[2] 能够有效管理通用任务并发，但在资源极限工况下，数学模型与物理约束之间的鸿沟常导致确定性挑战。因此，本文提出的 PRS 并非对传统理论的否定，而是作为一种针对关键物理契约的“场景化增强机制”。

---

## 2. Engineering Context: Complementing Traditional Theory (工程背景：对传统理论的补充)
Traditional scheduling is highly effective for stable, resource-rich environments. The PRS approach complements this by specifically addressing "Critical PRS Scenarios"—tasks that demand absolute punctuality under resource scarcity [3]. It acknowledges that while RMS handles the majority of system tasks, critical physical loops require a distinct management layer to guarantee Worst-Case Execution Time (WCET) without redesigning the underlying system.
传统调度在资源充沛的稳定环境中表现优异。PRS 通过专项应对“PRS 关键场景”——即资源紧缺下必须保障准时的任务——来补充这一架构 [3]。PRS 承认 RMS 负责系统绝大多数任务，但对于核心物理控制回路，需要一个独特的管理层，在不重构底层系统的前提下保障最坏执行时间 (WCET)。

---

## 3. Methodology: Scenario-Based Implementation (方法论：基于场景的工程实现)
PRS integrates with existing systems via a Scenario-Based Layer that activates only when critical conditions are met:
PRS 通过一个仅在特定关键条件触发时激活的“场景层”与现有系统集成：

1. **Same-Frequency Task Clustering (场景内同频聚类):** To maintain system integrity, tasks within a PRS scenario must share identical frequencies, ensuring the scenario operates as a unified, deterministic control loop. 为保持系统完整性，PRS 场景内的任务必须具备完全一致的频率，确保场景以统一的确定性控制回路运行。
2. **Unified Highest Priority & Sequential Execution (优先级统领与顺序执行):** Upon activation, scenario tasks are unified to the highest system priority. They are serialized to bypass context-switching overhead, effectively transforming the scenario into a high-performance "single-stream" process. 场景激活后，内部任务被统领至最高优先级，并按固定顺序串行（单流化），绕过上下文切换开销，形成高性能的单一逻辑流。
3. **Interrupt Masking for Jitter Control (中断屏蔽与抖动抑制):** PRS applies selective interrupt masking to eliminate external sources of execution jitter, converting random delay into a predictable system bias. PRS 配合选择性中断屏蔽机制，抑制外部执行抖动，将随机延迟转化为可预期的系统偏置。

---

## 4. Architecture & Reliability (架构与可靠性)
PRS ensures integration with standard RTOS designs:
PRS 通过以下设计与标准 RTOS 设计无缝对接：

- **Scenario-Based MPU Isolation:** Using MPU to partition scenario memory from background tasks without disrupting standard RTOS operations. 使用 MPU 将场景内存与后台任务分区，不干扰标准 RTOS 运作。
- **One-way Control Flow:** To prevent priority inversion, data flow is restricted from High-Priority scenarios to Low-Priority background tasks, maintaining system stability. 为防止优先级反转，数据仅允许从高优先级场景流向后台任务，保障系统整体稳定性。
- **Fast Automatic Recovery:** Recovery mechanisms are designed to be non-intrusive, ensuring that fault handling does not affect the deterministic timing of ongoing critical scenarios. 故障恢复机制被设计为非侵入式，确保故障处理不会干扰 PRS 关键场景的确定性时序。

---

## 5. Conclusion (总结)
In summary, PRS provides a practical engineering enhancement to traditional real-time scheduling. By introducing a scenario-aware layer, it enables systems to handle performance bottlenecks and resource constraints while retaining the flexibility of established RTOS models. It does not replace traditional theory; instead, it provides the deterministic safeguard required for core physical operations, ensuring that the most critical system contracts are fulfilled even under the most demanding conditions.
综上所述，PRS 为传统实时调度提供了一种实用的工程化增强方案。通过引入场景感知层，系统既能保留传统 RTOS 的灵活性，又能有效应对性能瓶颈与资源约束。PRS 并不取代传统理论，而是为核心物理操作提供了确定性保障，确保在极度苛刻的工况下，最关键的系统契约依然能够完美履约。
